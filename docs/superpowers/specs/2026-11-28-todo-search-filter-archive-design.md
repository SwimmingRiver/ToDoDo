# 할 일 검색·우선순위 필터·완료 보관함 설계

- 작성: 2026-11-28 (브레인스토밍 11-27~28, 사용자와 합의)
- 범위: **웹 먼저**(목록·칸반), 같은 규칙을 앱 1.1.0에 이식(목록만, 앱엔 칸반 없음)
- 관련: `docs/data-model/recurring-todos.md`(반복 회차 구조), 메모리 search-filter-decision·mobile-110-scope

## 1. 왜 하는가

- **검색**: 웹 목록엔 검색이 이미 있지만(01-18 `58fd16d`) ① 검색어마다 Firestore에서 할 일 전체를 다시 읽고(`getSearchTodoList` → `getTodos()`, 쿼리 키가 검색어별) ② 제목만 찾고 ③ 하위 할 일이 걸리면 부모 없이 낱장 카드로 따로 떠서 어느 프로젝트인지 모르고, 부모도 걸리면 같은 하위가 두 번 보인다. 앱엔 검색이 없다.
- **우선순위 필터**: 사용자 요청. 하위 할 일의 우선순위로도 찾게 될 것이라는 사용자 판단.
- **완료 보관함**: 완료된 프로젝트는 완료 즉시 목록에서 숨겨지고(`status !== "done"`), 30일이 지나면 `archived: true`가 되어 아예 받아 오지 않는다. 웹은 30일 안의 것만 칸반 Done에서 낱장으로 보이고, **앱은 완료 프로젝트를 볼 곳이 전혀 없다.** 사용자 표현으로 "완료 노출을 줄인 것에 대한 보상" — **지난 기록 확인용, 읽기 전용.**

## 2. 목표 / 비목표 / 반목표

**목표**
- 목록: 검색(제목+설명) + 우선순위 칩(다중 선택) + `진행 중 | 완료` 전환
- 칸반: 같은 검색 + 칩
- 판정 규칙 하나를 웹(목록·칸반)과 앱이 함께 쓴다

**비목표**
- 서버 검색, 검색용 요약 문서, Worker 정제 API, 페이지 나누기 — 검토 후 기각(11-27). 클라이언트 SDK는 필드 선택이 안 되고, 데이터 양은 30일 아카이빙으로 이미 제한된다.
- 보관함에서 되살리기·삭제·수정 (읽기 전용)
- 오늘·캘린더 화면 검색 (사용자: 각 화면 취지에 맞게 목록에만)
- 날짜·상태 필터, 태그
- `overdueArchived`(놓친 반복 회차를 조용히 접은 것)는 보관함 대상이 아니다

**반목표 (기술적으로 돌아가도 실패인 것)**
- 검색·필터 때문에 Firestore 읽기가 늘어나는 것 (보관분을 처음 여는 1회 조회만 허용)
- 보관함에서 할 일 상태가 바뀌어 `archived: true`인 채로 목록 어디에도 안 보이는 할 일이 생기는 것
- 반복 할 일이 회차 수만큼 결과를 도배하는 것
- 웹과 앱의 판정 결과가 달라지는 것

## 3. 접근 방식 (검토한 것)

| 안 | 내용 | 결과 |
|---|---|---|
| A. 칸반 Done을 보관함으로 확장 (웹) | Done 열 아래 "30일 지난 완료 보기" | 기각. 칸반은 끌어서 상태를 바꾸는 보드라 보관분을 끌면 `archived: true`로 남아 사라짐. 앱엔 칸반 없음 |
| **B. 목록에 `진행 중 | 완료` 전환 (웹·앱 같은 구조)** | 프로젝트 단위, 월별, 읽기 전용 | **선택(사용자 11-28).** 칸반 Done(최근 상태 다루기)과 역할이 나뉨, 앱 이식이 쉬움 |
| C. 웹은 A, 앱은 B | 플랫폼별 기존 구조 | 기각. 규칙·테스트가 두 벌 |

추가로 사용자 요청: **칸반에도 검색+칩** (B에 더함, 크기 S).

## 4. 판정 규칙 (공용)

**`matchesTodoFilter(todo, { query, priorities }) → boolean`** — 할 일 하나 단위.

- `query`: 앞뒤 공백 제거, 비면 통과. 제목 또는 설명(`description`, 없으면 빈 문자열)에 **부분 일치**. 대소문자 무시, 양쪽 모두 NFC 정규화 후 비교(한글 자모 분리 입력 대비).
- `priorities`: 빈 집합이면 통과, 아니면 `todo.priority`가 집합에 포함.
- 둘 다 만족해야 걸림(AND).
- 순수 함수. **`packages/core`에 새 모듈**(예: `packages/core/src/todoFilter/`)로 두고 웹은 `@tododo/core/dist/todoFilter/index.js` 하위 경로로 import(루트 import 금지 — 기존 함정), 앱은 core에서 import.

## 5. 목록 화면 (웹 `todoList.tsx`, 앱 `TodoListScreen.tsx`)

### 5.1 데이터

- `진행 중` 탭: 지금처럼 `useGetTodos()`(`["todos"]`, archived==false) 결과만 사용. **추가 조회 없음.**
- `완료` 탭: ① `useGetTodos()` 결과의 완료 루트 + ② `archived == true` 조회 결과를 합친다.
  - ②는 `완료` 탭을 **처음 열 때만** 조회(`enabled`로 지연). 새 API `getArchivedTodos()` = `where("userId","==",uid), where("archived","==",true)`. 등호 조건 2개라 새 복합 인덱스 불필요(기존 `archived==false`와 같은 모양) — 구현 시 에뮬레이터/운영에서 확인.
  - **쿼리 키는 `["todos"]` 밖**에 둔다(예: `["archivedTodos"]`). `["todos"]` 아래 두면 할 일 하나를 고칠 때마다 기존 훅들의 `invalidateQueries({ queryKey: ["todos"] })`에 같이 무효화돼, 완료 탭을 다시 열 때마다 쌓이기만 하는 보관 문서 전체를 다시 읽는다(빌더 검토 지적, 11-28 결정).
  - 무효화는 보관분이 실제로 바뀌는 경로에서만: ① 앱 진입 스윕 `useRunStartupMaintenance`의 `written > 0`일 때(지금 `["todos"]` 무효화 옆에 추가 — written엔 다른 스윕 쓰기도 섞이지만 드물어서 허용) ② 반복 시리즈 삭제(`useDeleteRecurringSeries`)처럼 보관된 회차까지 지울 수 있는 경로. 보관함은 읽기 전용이라 그 밖의 경로는 없다. `staleTime`은 길게(예: `Infinity` 또는 30분).
  - 같은 id가 ①②에 동시에 있을 수 없지만(archived 값이 다름) 합칠 때 id로 중복 제거.
- 기존 `getSearchTodoList`·`useSearchTodo`·`["searchTodoList", q]` 쿼리는 **제거**(검색어마다 Firestore 재조회하던 경로).

### 5.2 진행 중 탭 결과

- 판정은 할 일 단위(부모·하위 각각 4절 규칙), **표시는 프로젝트 카드 단위**.
- 루트 후보: 지금 목록과 같은 규칙 — 루트 && `status !== "done"` → `collapseRecurringInstances`로 반복 시리즈당 대표 1건.
- 카드 표시 조건: 루트가 걸렸거나, 그 루트의 하위 중 하나라도 걸림.
- 하위만 걸린 카드: **자동 펼침**, 걸린 하위 강조, 안 걸린 하위는 흐리게(맥락 유지).
- 하위 단독 카드(`ChildTodoCard`를 결과에 따로 내던 것)는 없앤다 → 중복 표시 해소.
- 검색어·칩이 모두 비면 지금 목록과 완전히 같다(회귀 없음).

### 5.3 완료 탭

- 대상: 완료 루트(`parentId === null && status === "done"`) — 최근분 + 보관분. 하위는 각 루트 아래.
- **반복 할 일의 완료 회차: 시리즈당 한 장, 달마다 나눔 (사용자 11-28 A안).** 회차마다 문서가 따로라 그대로 두면 매일 반복을 한 달 완료했을 때 같은 제목 카드가 30개 생긴다.
  - 묶는 키: `(recurrenceId, 완료 월)`. **최근분과 보관분을 합친 뒤** 묶는다(보관 스윕이 회차를 루트 단위로 따로 보관해서 한 시리즈가 양쪽에 섞여 들어온다).
  - 카드: 제목 + "N회 완료" + 그달 마지막 완료일("MM-DD 완료"). 10월에도 완료했으면 10월 묶음에 별도 카드.
  - 카드 내용(설명 등)은 그달 마지막 완료 회차 것을 쓴다. 반복 회차는 하위 할 일이 없는 게 원칙(`docs/data-model/recurring-todos.md`, 반복은 루트에만)이라 펼치면 설명만.
  - 검색·칩: 묶음 안 회차 중 하나라도 걸리면 카드 표시(회차는 시리즈 정보를 복사하므로 보통 모두 같은 결과).
  - 결과 수는 카드 수 기준.
  - `recurrenceId`가 없는 일반 완료 루트는 지금처럼 한 장씩.
- 진행 중 프로젝트 안의 완료된 하위는 지금처럼 진행 중 탭의 프로젝트 안에 남는다(완료 탭에 따로 안 나옴).
- 정렬: 완료일 최신순, **월별 묶음**(기기 로컬 시각 기준 — 통계 `insights/date.ts`와 같은 방식, 판매 국가가 한국뿐이라 서울 기준과 같음). 완료일 = `doneAt`, 없으면 `updatedAt`(옛 문서 대비 — 11-23 백필 후 0건이지만 방어).
- 검색·칩 규칙은 5.2와 같다(하위만 걸리면 펼침).
- **읽기 전용**: 카드 수정·삭제·하위 추가·상태 변경 메뉴 없음. 카드를 누르면 상세 화면으로 가지 않고 **펼치기만**(하위 목록 + 설명). 상세 화면은 수정 화면이고, 보관분은 목록 쿼리에 없어서 상세가 따로 읽어야 하며, 읽기 전용 상태를 새로 만들어야 하므로 이번엔 하지 않는다.
- 완료 카드 표시: 체크 표시 + "MM-DD 완료".
- 빈 상태: "완료한 프로젝트가 아직 없어요" / 필터 결과 없음은 기존 검색 빈 상태 재사용.

```
┌ 할 일 ─────────────────────────────┐
│ [진행 중] [ 완료 ]                   │
│ 🔍 할 일 검색...                     │
│ (높음) (보통) (낮음)                 │
│ 2026년 11월                          │
│  ✓ 기말 과제 제출        11-20 완료   │
│    ▸ 하위 3개                        │
│ 2026년 10월                          │
│  ✓ 이사 준비            10-02 완료   │
└─────────────────────────────────────┘
```

### 5.4 상태 보존 (웹)

- 탭·검색어·칩은 **URL 쿼리**(`?tab=done&q=...&p=high,medium`)에 둔다. 진행 중 카드 → 상세 → 뒤로 가기 때 유지(#253 캘린더 URL 상태와 같은 방식, `useSearchParams`). 입력 중 매 글자마다 히스토리가 쌓이지 않게 `replace`.
- 앱은 화면 상태(useState)로 충분(스택 내비게이션에서 뒤로 가도 화면이 살아 있음) — 이식 때 확인.

## 6. 칸반 (웹만)

- 상단에 같은 검색창 + 칩. 상태 보존은 목록과 같은 URL 쿼리 키(`q`, `p`)를 쓰되 칸반 라우트 자체 값.
- 칸반은 할 일이 원래 낱장 카드라 **걸린 카드만 남긴다**(묶음·펼침 없음). 열 분리 전에 `matchesTodoFilter` 적용. 기존 `isVisibleInKanban`(미래 반복 회차 숨김)은 그대로 함께 적용.
- 끌기: **열 사이 이동(상태 변경)은 허용**, 필터가 켜진 동안 **같은 열 안 순서 바꾸기는 막는다**. 기존 재정렬은 숨겨진 카드까지 포함한 전체 기준이라 데이터는 안전하지만(`useKanbanDrag.ts:90-98`), 숨긴 카드 사이 어디에 들어가는지 사용자에게 안 보이기 때문.
- 칸반은 보관분을 받아 오지 않는다(지금처럼 최근 30일).

## 7. 공용 UI

- 검색창: 기존 `TodoSearch` 재사용. 로컬 필터라 로딩 스피너는 필요 없음(제거 또는 미사용). 디바운스는 짧게 유지해도 되고 없애도 됨(빌더 판단).
- 우선순위 칩: 새 컴포넌트(예: `PriorityFilterChips`), 다중 토글, 라벨 높음/보통/낮음. 앱엔 비슷한 `PriorityChips`(단일 선택 세그먼트)가 있으나 다중 선택이라 별도.
- 결과 수 표시: 기존 `resultCount` 자리 — 프로젝트 카드 수 기준.
- 색은 `client/CLAUDE.md` 브랜드 토큰 규칙(`brand.fill`에 글자 금지), 다크 모드 대응.

## 8. 테스트

- core `matchesTodoFilter`: 제목/설명/대소문자/NFC/빈 값/AND.
- 목록 파생(웹): 하위만 걸림 → 부모 카드+자동 펼침, 부모·하위 모두 걸림 → 한 번만, 반복 시리즈 1건, 필터 비면 기존과 동일.
- 완료 탭: 최근+보관 합치기·중복 제거, 월 묶음(**TZ=America/New_York로도 실행** — UTC 저장 함정), doneAt 없음 폴백, 읽기 전용(메뉴 없음).
- 보관 조회가 `완료` 탭을 열기 전엔 실행되지 않음(Firestore 읽기 0 확인), 할 일을 고친 뒤 완료 탭을 다시 열어도 재조회하지 않음(스윕 written>0·시리즈 삭제 때만 무효화).
- 반복 완료 묶음: 같은 시리즈가 최근분·보관분에 나뉘어 있어도 한 달에 한 장, 달이 다르면 따로, "N회"·마지막 완료일 정확.
- 칸반: 필터 시 같은 열 재정렬 비활성, 열 이동은 동작.
- CI 등가: `VITE_FIREBASE_API_KEY= npx vitest run`.

1. core 판정 함수 → 2. 웹 목록(검색 경로 교체 + 칩 + 완료 탭) → 3. 웹 칸반 → develop PR. 12-01~12-21 main 릴리스에 실을 수 있으면 싣는다(#249 rules 때문에 12-01 이후).
2. 앱 이식(목록만)은 1.1.0 — 웹이 확정된 뒤.

## 10. 설계자(Claude)가 정한 것 — 사용자 확인용

- 판정 함수를 `packages/core`에 두고 NFC 정규화·대소문자 무시
- 탭·검색어·칩을 URL 쿼리에 보존(웹), `replace`로 히스토리 안 쌓기
- 완료 탭 카드는 누르면 펼치기만(상세 화면으로 안 감)
- 완료 월은 기기 로컬 시각(통계와 같음), `doneAt` 없으면 `updatedAt` 폴백
- 보관분 쿼리 키를 `["todos"]` 밖에 두고 스윕·시리즈 삭제 때만 무효화
- 칸반은 필터가 켜진 동안 같은 열 안 순서 바꾸기만 막음
