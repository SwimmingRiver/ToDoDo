# 스크린샷 데모 데이터

스크린샷은 공개 자료이므로 실제 개인 데이터를 쓰지 않는다. 운영 Firebase를 쓰되 **전용 데모 계정 하나에만** 데이터를 넣는다. 다른 사용자의 데이터는 건드리지 않는다.

## 넣는 방법 — 제안

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **1 (추천)** | 데모 Apple ID(또는 Google 계정)로 앱에 가입 → `scripts/seedDemoTodos.ts`(`npm run seed:demo`)로 그 uid에만 할 일을 넣음 → `grant:entitlement`로 프리미엄 부여 | 날짜가 실행일 기준으로 계산돼 언제 찍어도 "오늘"이 꽉 찬다. 다시 찍을 때 `--reset`으로 지우고 재생성 가능. 심사 데모 계정과 같이 쓸 수 있음 | 스크립트 작성 필요(작음, grantEntitlement와 같은 admin SDK 패턴) |
| 2 | 데모 계정으로 앱에서 손으로 입력 | 코드 없음 | 20여 개 입력, 다시 찍을 때마다 날짜가 지나 다시 입력 |
| 3 | 에뮬레이터 + 로컬 앱 | 운영 완전 분리 | 통계·AI 플랜·캘린더 연동은 Worker까지 로컬로 띄워야 해 손이 많이 감 |

스크립트 안전장치(1안): `--uid` 필수, 대상 계정 이메일이 허용 목록(데모 계정)과 다르면 거부, 생성 문서에 표식 없이도 `--reset`은 그 uid 문서만 지운다. 반복 할 일은 스크립트가 회차 생성 규칙(`docs/data-model/recurring-todos.md`)을 재구현하지 않도록 **앱에서 손으로 2개만 만든다**(아래 ★). → 1안 승인(11-23), 스크립트 추가함. 아래 §사용 절차.

## 데모 할 일 세트 (D = 시드 실행일)

화면 후보 순서는 `docs/mobile-release.md` §스크린샷과 같다.

### 1. 오늘 화면 — D에 6개, 그중 2개 완료(진행률 33%)

스크립트는 ★ 없는 4개(완료 1개)를 넣고, ★ 2개는 앱에서 만들고 "아침 스트레칭"을 완료 처리한다.
| 제목 | 우선순위 | 일정 | 상태 |
|---|---|---|---|
| ★ 아침 스트레칭 10분 | 보통 | 매일 반복 07:30 | 완료 |
| 팀 주간 회의 자료 정리 | 높음 | D 10:00 마감 | 진행 중 |
| 운동 — 러닝 5km | 보통 | D 19:00 | 할 일 |
| ★ 영어 단어 30개 외우기 | 낮음 | 매주 월·수·금 | 할 일 |
| 장보기 (우유, 달걀, 사과) | 낮음 | D 18:00 | 완료 |
| 디자인 시안 피드백 회신 | 높음 | D 17:00 마감 | 할 일 |

주간 날짜 줄에 점이 찍히도록 D-2~D+4에 1~3개씩 더 분산(아래 프로젝트 하위 할 일이 자연스럽게 채움).

### 2. 목록 — 하위 할 일이 있는 큰 일 3개
- **포트폴리오 사이트 완성** (높음, 마감 D+21) — 하위: 레퍼런스 조사(완료) · 와이어프레임(완료) · 메인 페이지 디자인(진행 중, D+3) · 프로젝트 소개 글 작성(D+7) · 배포(D+20)
- **이사 준비** (보통, 마감 D+14) — 하위: 이삿짐센터 견적 비교(완료) · 전입신고(D+15) · 인터넷 이전 신청(D+5) · 버릴 짐 정리(D+2)
- **제주도 여행 계획** (낮음, 마감 D+30) — 하위: 항공권 예매(완료) · 숙소 예약(D+4) · 일정표 만들기(D+10)

### 3. AI 플랜 — 목표 입력 예시
`다음 달까지 토익 800점 만들기` (마감 D+30) → 생성된 미리보기 화면을 찍는다(저장 전). 실제 AI 호출이라 결과가 매번 다르니 잘 나온 것을 고른다. 하루 횟수 제한(20회) 주의.

### 4. 캘린더 — 월간
위 할 일들의 마감이 이달에 퍼져 보이도록 이미 배치됨. 구글 캘린더 오버레이는 **데모용 구글 계정**을 연동하고 그 계정 캘린더에 일정 3~4개(예: "치과 예약", "친구 생일 저녁", "분기 회의")를 만들어 둔다. 개인 구글 계정 연동 금지.

### 5. 통계 — 지난 4주 완료 기록
통계는 `doneAt` 기준이라 스크립트가 D-28~D-1에 완료 할 일 30~40개를 하루 0~3개씩 넣는다(연속 달성일이 보이게 최근 7일은 매일 ≥1). 우선순위는 높음:보통:낮음 ≈ 3:5:2. `archived` 대상(30일 지난 done)이 되지 않게 D-28 이내로만.

### 6. 할 일 상세 — ★ 영어 단어 30개 외우기 (매주 월·수·금, 종료일 D+60)

## 사용 절차

**11-26 데모 계정 생성·시드 완료**: 데모 전용 Google 계정 `tododo.demo@gmail.com`(2단계 인증 끔, 심사 로그인 정보와 같은 계정). uid와 비밀번호는 저장소에 적지 않는다(Firebase 콘솔 Authentication에서 이메일로 찾는다). 시드 51개(11-26 기준) + manual 프리미엄(2099-12-31) + 반복 2개를 앱에서 만들었다. 구글 캘린더 오버레이는 연동하지 않고 찍었다. 다시 찍을 때는 아래 순서를 그대로 따른다. 운영 Firebase에 쓰므로 `--uid`와 허용 목록을 꼭 데모 계정으로 맞춘다.

1. **데모 계정 만들기**: 데모 전용 Apple ID(또는 Google 계정)로 앱에 가입한다. Apple "이메일 가리기"를 고르면 Auth 이메일은 `…@privaterelay.appleid.com` 주소가 된다 — 허용 목록에도 그 주소를 넣는다.
2. **uid·이메일 확인**: Firebase 콘솔 → Authentication → 사용자에서 그 계정의 사용자 UID와 이메일을 확인한다. 저장소에 적지 않는다.
3. **시드(dry-run → 실제)**: 서비스 계정 키는 `grant:entitlement`과 같은 것(Cloud Datastore User + Firebase Admin SDK Administrator Service Agent 역할).
   ```bash
   export GOOGLE_APPLICATION_CREDENTIALS=<키 경로>
   export DEMO_SEED_ALLOWED_EMAILS=<데모 계정 이메일>   # 여러 개면 쉼표로
   npm run seed:demo -- --uid <uid>            # dry-run: 생성 예정 개수만 출력
   npm run seed:demo -- --uid <uid> --apply    # 실제 쓰기(약 50개, 그중 통계용 완료 기록 30~40개)
   ```
   - 이메일이 허용 목록에 없으면 아무것도 하지 않는다. 이미 할 일이 있으면 거부한다(중복 방지).
   - **다시 찍을 때**: `--reset --apply`로 그 uid의 `todos`만 지우고 오늘 기준으로 다시 넣는다. 앱에서 만든 ★ 반복 2개도 같이 지워지므로 4·5단계를 다시 한다. 캘린더 연동 중이면 지워진 할 일의 구글 이벤트 정리는 앱 동기화에 맡긴다.
   - 날짜는 실행 시각의 **KST 날짜**가 D다. 찍는 날 실행한다.
4. **프리미엄 부여**: `npm run grant:entitlement -- --uid <uid> --plan premium` (통계·AI 플랜·캘린더 연동 화면용).
5. **반복 2개 손으로 만들기**(앱): ★ 아침 스트레칭 10분(보통, 매일, 07:30) → 완료 처리 / ★ 영어 단어 30개 외우기(낮음, 매주 월·수·금, 종료일 D+60). 진행률이 2/6 = 33%가 되는지 본다.
6. **구글 데모 캘린더**: 데모용 구글 계정 캘린더에 일정 3~4개를 만들고 앱에서 연동한다(§4). 개인 계정 금지.
7. 촬영(§촬영 규격).

에뮬레이터로 먼저 볼 때는 `FIRESTORE_EMULATOR_HOST`·`FIREBASE_AUTH_EMULATOR_HOST`(둘 다)·`GCLOUD_PROJECT`를 설정하면 키 없이 에뮬레이터로 간다.

## 촬영 규격

- **실제 규격(11-26 제출 화면)**: 칸 이름은 "15.5cm 또는 15.9cm 디스플레이의 iPhone"(중형, Dynamic Island)이고 **1179×2556 또는 1206×2622만** 받는다. 6.9형(1320×2868)은 거절됐다. iPhone 전용이라 iPad·Watch·iPhone Duo 칸은 비운다.
- 촬영: **iPhone 18 Pro 시뮬레이터(1206×2622)** + `xcrun simctl io booted screenshot <파일>`. 시뮬레이터 앱은 EAS `simulator` 프로필 빌드를 `eas build:run`으로 설치한다(Xcode 27은 Simulator.app 대신 `Xcode.app/Contents/Applications/DeviceHub.app`). 터치 자동화 도구가 없어 화면 이동은 사람이 한다.
- 11-26 제출본은 Pro Max로 찍어 `sips --resampleHeightWidth 2622 1207` 후 `--cropToHeightWidth 2622 1206`, JPEG(알파 없음)로 변환했다. 순서: 오늘 → AI 플랜(맨 위 "AI가 만든 계획"이 보이게) → 목록(하위 할 일 펼침) → 캘린더(오늘 날짜를 눌러 시트를 연 상태) → 통계 → 상세(반복 요일이 보이게 스크롤). 구독 심사용은 무료 계정의 계정 화면(체험 버튼·고지 문구).
- 함정: 오후에 찍으면 오전 마감 할 일에 빨간 "○시간 지남"이 붙는다 → 그 할 일의 마감을 저녁으로 옮기거나 완료 처리 후 찍는다. 상태 막대 정리: `xcrun simctl status_bar booted override --time 9:41 --batteryState charged --batteryLevel 100 --cellularBars 4`.
- 라이트 모드로(앱이 `userInterfaceStyle: light`).
- 프리뷰 영상은 선택 — 이번엔 생략 추천.
